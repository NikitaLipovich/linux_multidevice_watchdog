## Что матрица ПОЙМАЛА (ценность прогонов)
1. **[Python, ИСПРАВЛЕНО] GC-ловушка:** `monitor_config_changes` (несёт пульс udp_logger) создавался голым `create_task` без сильной ссылки → после N рестартов задача собиралась GC → пульс мёртв при живом сервисе. Fix: strong ref + cancel в teardown.
2. **[Python, ИСПРАВЛЕНО] Ложно-живой пульс:** config_server лежал (health 000), а его пульс-корутина продолжала биться. Fix: beat гейтится TCP-самопробой :8000 (ws_bridge — is_serving).
3. **[Конфиг, ИСПРАВЛЕНО] grace 40с мал:** полный цикл initd stop(≤10с SIGKILL)+boot(25–35с)+первый пульс — wd добивал стартующий процесс. → 90с.
4. **[C, ИСПРАВЛЕНО в G2] Consumed-без-возврата:** после съеденного crash-файла wd ждал пульс вечно; теперь повторная попытка по delay-гейту.
5. **[ФУНДАМЕНТАЛЬНОЕ, НЕ исправлено — развилка]** см. ниже.
6. **[Наблюдаемость] Wall-clock прыгает** (data_uploader time_sync/RTC дёргает системное время) → порядок строк wd.log нечитаем в шторм. Надо добавить `up=<monotonic_s>` в каждую строку лога (5 строк C).
7. **[Тест-скрипт] Тайминги матрицы** должны закладывать grace+boot с запасом (v2 промахнулась окнами на двойном рестарте).

## РАЗВИЛКА (фундаментальное): «мягкий рестарт сервиса» упирается в teardown «Единого»
Факт с живого стенда: **data_uploader не пере-поднимается мягко ВООБЩЕ** — его GPS-сервер держит TCP:1111 в осиротевших задачах, teardown их не убивает → factory при каждом пересоздании падает `[Errno 125] address in use` → сервис молчит навсегда → wd эскалирует в рестарт процесса (шумно, минуты). Также при рестартах data_uploader копятся дубли time_sync/NTP-циклов (шторм логов, CPU). config_server при серии мягких рестартов тоже флапал. Чисто мягко рестартится только udp_logger (его teardown полный: cancel monitor + close datagram-серверов).

**Это не дефект C-демона.** Это предел run_services.py: сервисы «Единого» не проектировались под горячее пересоздание (нет stop()-API у оркестратора, серверов, циклов). Watchdog честно вскрыл это.

### Варианты (решение пользователя)
- **A. Чинить teardown всех 4 сервисов** — «правильный» путь: stop()-API оркестратору data_uploader (гасить gps_server/mqtt/time_sync/realtime-listener), аудит config_server/ws_bridge. Заметная Python-работа, выходит за «минимальный вотчдог», но делает мягкий рестарт реальным для всех.
- **B. v1-прагматика (≈15 строк C + 3 строки конфига):** новое значение `action=restart_process` per-service; для data_uploader/config_server/ws_bridge тихая смерть → сразу рестарт процесса (штатный procd-путь, чистый старт всего), udp_logger остаётся мягким. Честно отражает сегодняшнюю реальность «Единого»; teardown-долг фиксируется в бэклог.
- (после выбора: домотать матрицу v3 с запасами по таймингам → шаг 6 (реальный флеш) с пользователем → verify_all → DONE)
